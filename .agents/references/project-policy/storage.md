# Worktree и хранение evidence

- Для нового обычного Git worktree используй `python3 tools/worktree_storage.py create <absolute-path> --branch codex/<change> --ref main`. Helper настраивает sparse checkout до выгрузки HEAD. Код, корневые документы `docs/` (включая GAME_SPEC) и `docs/tasks/` остаются; исторические подпапки `docs/` и `artifacts/` не выгружаются. Нужные архивные файлы читай точечно через `git show <revision>:<path>` или из общего evidence_root. Когда конкретной проверке действительно нужно полное историческое дерево, расширь sparse selection в собственном worktree.
- В Codex-managed worktree используется setup script и установленный post-checkout hook. Они применяют ту же выборку после первоначального checkout: это уменьшает постоянный размер, но не устраняет пиковое первоначальное копирование. Primary checkout, обычные переключения веток, существующие custom sparse selection, dirty worktree и локальные/ignored evidence автоматически не меняются. Не применяй prepare к чужому активному worktree.
- В `docs/` и `artifacts/` сохраняй только компактные текстовые документы, manifests и ссылки. Временные raw logs, XML/CSV, кадры, видео, архивы и промежуточные сборки пиши в игнорируемый `.local/<task>/`. Уникальные постоянные доказательства и материалы открытой приёмки сохраняй один раз в `evidence_root` из `workflow/project.json`, под planning lease, с source revision и hashes. Исходные игровые ассеты остаются в `unity/Assets/` или их source-каталоге; правило не запрещает продуктовые ассеты.
- `make storage-check`, pre-commit hook и PR check проверяют только добавленные/изменённые `docs/`/`artifacts/`: отклоняют raw/binary evidence и документы больше 1 МиБ. Исторические неизменённые blobs не блокируют работу. Перенеси payload в подходящее хранилище и оставь краткий отчёт/ссылку; не отключай check ради QA-данных.
- Накопленные tracked evidence убирай отдельным сохранённым изменением только после проверки owner, статуса приёмки, интеграции и ссылок. Перед удалением единственной копии перенеси её в общий store и проверь hashes; запись о переносе должна сохранять прежний путь и точный source revision. Не удаляй evidence открытого FAIL/NotRun или незавершённой задачи по возрасту.
- Для уже сохранённого исторического пакета допустим компактный индекс в общем store: immutable code commit, прежние пути, Git blob IDs и SHA-256. Если commit сохраняется в ancestry `main`, байты можно оставить в существующей Git-истории, убрав только копии из текущего code tree; не создавай второй архив того же содержимого и не переписывай историю. Оставь STORAGE.md с точной командой восстановления.

После интеграции helper один раз устанавливает репозиторные hooks командой `python3 tools/worktree_storage.py install-hooks`. Существующие пользовательские hooks и core.hooksPath не перезаписываются. Браузеры, Unity, Player/build/deploy этой процедурой не запускаются.
